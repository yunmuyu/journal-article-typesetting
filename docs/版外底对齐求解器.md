# 版外底对齐求解器

`JournalBottomSolver.psm1`只在 Adobe 外计算一次性调整计划。它不打开 InDesign、不修改文档，也不生成空白段、上内边距、首行偏移或垂直分散。装配程序应在批量置入完成后提供实际测量值，应用返回计划，再统一重排。

## 输入

入口：

```powershell
.\2-导入_InDesign\New-JournalBottomPlan.ps1 `
  -InputPath "文章底对齐输入.json" `
  -OutputPath "文章底对齐计划.json"
```

JSON 顶层字段：

- `version`：固定为 `1`。
- `tolerancePt`：允许残差，默认 `0.25 pt`，范围 `(0, 1]`。
- `columns`：逐栏测量。`targetBottomPt-currentBottomPt`为所需高度变化；正数表示内容需向下增加，负数表示需收紧。

每栏必须提供唯一`id`、`currentBottomPt`、`targetBottomPt`及以下四个数组（没有候选时为空数组）：

- `leadingGroups`：`id`、`kind`、`lineCount`、`currentPt`、`minPt`、`maxPt`。默认按 `lineCount-1` 个基线间隔计算高度变化；若调用方已从版面得到更精确数量，可传 `baselineIntervals`（0至`lineCount`的整数）。`body`自动限制到14.8–16 pt；`reference`自动限制到12.6–13.4 pt，即13 pt上下最多0.4 pt。
- `trackingCandidates`：`id`、`current`、`lineHeightPt`和预先排算的`outcomes`。每个结果含`tracking`、相对当前排版的整数`lineDelta`及`orphanFree`。求解器只采用`orphanFree:true`且字距绝对值不超过20的结果；必须包含当前字距、`lineDelta:0`的基准结果。候选结果应在预检阶段排除单字行、行首引文上标、数字串及数值单位断行。
- `figures`：`id`、`currentHeightPt`、`currentScalePct`、`minScalePct`、`maxScalePct`。无论输入范围多大，求解器最多允许相对当前比例上下5%；建议预检按实际图质给更窄范围。
- `tableRows`：`id`、`singleLine`、`count`、`currentHeightMm`、`minHeightMm`、`maxHeightMm`。只调整`singleLine:true`，并强制4.8–5.5 mm；多行单元格保持自然高度。

示例：

```json
{
  "version": 1,
  "tolerancePt": 0.25,
  "columns": [{
    "id": "page-2-left",
    "currentBottomPt": 746.2,
    "targetBottomPt": 750.0,
    "leadingGroups": [{
      "id": "body-lines", "kind": "body", "lineCount": 24,
      "currentPt": 15, "minPt": 14.8, "maxPt": 16
    }],
    "trackingCandidates": [],
    "figures": [],
    "tableRows": []
  }]
}
```

## 确定性选择

求解器按固定阶段寻找第一个可解方案：行距；行距加局部字距；再加小幅图高；最后再加单行表高。同一阶段按候选ID、字距改变量和效果稳定排序；连续变量按各自可用容量同比分配，避免先把某一段或某一行推到极值。相同输入会产生字节顺序一致的JSON结构。

输出`status:ready`时，每栏给出`stage`、所需与已实现高度、残差及逐项`from/to/effectPt`，供一次JSX装配调用应用。`adobeCalls`固定为0，`blankSpaceAllowed`固定为false。

任一栏无法在容差内求解时，顶层和该栏均为`status:blocked`，错误码为`BOTTOM_UNSOLVABLE`；入口仍先写出诊断计划，然后抛出`BOTTOM_PLAN_BLOCKED`阻断排版队列。阻断计划的`adjustments`为空，不能把“最接近”的部分结果写入InDesign。

## 回归

```powershell
.\tests\run_bottom_solver_regression.ps1
```

回归不启动Adobe，覆盖正文与参考文献行距边界、无孤字字距候选、图/表上限、负向收紧、不可解阻断、重复运行确定性及文件入口。

## 一次性写入 InDesign

求解输入的每个候选可带 `target`，求解器会原样写入被选中的调整：

- 行距、字距：`{"storyRole":"body","startIndex":10,"endIndex":30}`，索引为已绑定文章故事中的字符范围。
- 图片：`{"label":"source-figure-3"}`，标签在当前文章范围内必须唯一。
- 表行：`{"tableLabel":"source-table-1","rowIndex":0}`，`rowIndex`从0开始。

文章配置可直接嵌入 `bottomPlan` 对象，也可填写 `bottomPlanPath`；相对路径按文章配置所在目录解析。若二者同时存在，嵌入对象优先。`bottomPlan`本身也可以是路径字符串，供旧清单迁移使用。

Apply入口在进入COM前拒绝非`ready`计划。单次JSX事务先完成字体、几何、孤字及图块准备，再调用`JournalBottomPlan.apply`：它先验证全部动作和目标，任何一项非法时整批不写；全部通过后依次写入行距、字距、图片等比比例与表行最小高度，只调用一次`recompose()`，随后运行原审计。存在计划时不会调用内部`alignBottom`试探循环；没有计划的旧配置仍走原路径。

`journal_bottom_plan.jsxinc`再次拒绝空白、spacer、inset、vertical、whitespace类动作，并重新核对所有数值边界。调用方不能以手改JSON绕过版外求解器约束。

```powershell
.\tests\run_bottom_plan_apply_regression.ps1
```

该回归以Node假文档验证四类调整、预验证原子性、单次重排、blocked计划和空白动作阻断，不启动Adobe。
