# 期刊排版规则程序运行说明

规则已经接入通用导入器和独立排版检查入口，不依赖赵志威、张芳芳的专用修订脚本。当前版本处理已装配文章的规范化与检查；图表装配、文章核对输入和故事绑定仍需按文章准备，不代表任意Word可直接全自动成稿。

## 入口

- import_word_article_to_indesign.jsx及0文章.jsx：导入正文、摘要角色和作者简介时设置规定格式，清理继承字符格式，保留源上下标/斜体。摘要标签Absrtact纠正为Abstract。规定字体不可用时中止，不悄悄退回其他正文字体。
- journal_layout_rules.jsxinc：共享规则，规范摘要与简介、灰框、图题间隔、真实表头、图片居中、默认左页起排及底线。规则检查与排版修复分开，程序不擅自移动结论中的图或改正文。
- journal_layout_and_check.jsx：InDesign脚本面板入口，选择文章JSON配置，处理测试副本并生成版面审计。它不做完整Word内容对照，弹窗已明确提示，不能只据此交付。
- Invoke-JournalLayout.ps1：完整入口，调用同一模块，再逐段/逐单元格/上下标与原稿解析输入对照，校验图源指纹与尺寸，发现错误抛异常、返回失败。

## 命令

从项目2-导入_InDesign目录运行：

```powershell
.\Invoke-JournalLayout.ps1 -ConfigPath "文章配置.json" -Mode Apply -ExportPreview
.\Invoke-JournalLayout.ps1 -ConfigPath "文章配置.json" -Mode Check
```

Apply先保存恢复副本，再规范版面、生成审计、保存QA候选稿、导出IDML及可选页面预览。候选稿保存不表示验收通过，以对应audit.result.json的passed和errors为准。Check用于检查已排文章。原生调用失败会明确记录passed:false，避免沿用旧成功状态。

运行前必须有文件名含QA、copy或副本的测试文件；程序拒绝普通生产文件名。正式文件、模板、Word与原图保持只读。修改脚本后运行deploy_to_indesign.ps1 -NoPause；部署到脚本面板“期刊文章自动排版系统”子目录，会备份该子目录旧文件，并核对导入器两个入口、共享模块和菜单入口的SHA256。

## 文章配置

两篇已验证配置位于本次交付的“配置”目录。字段说明：

| 字段 | 用途 |
|---|---|
| documentPath | 测试INDD路径 |
| bindings | 本稿各story的id及role：front、body、footer、doi、figures；首次注册后以journal-role标签查找 |
| sourceParagraphs | 从对应Word提取的全文段落及上下标核对输入，不是从InDesign反向生成的基准 |
| sourceTables | Word表格二维单元格数据，支持顶层tables或表格数组 |
| figureCount、graphicCount、tableCount | 应有图题、图形链接和表格数；公式图形计入graphicCount |
| pageBudget | Word文件名中的预计页数 |
| startOnLeft | 默认true；右页起排时改为下一偶数页并调整奇偶页版心 |
| assets | 已核对的图表公式文件名、尺寸、路径和SHA256；换图必须重新核验基准 |
| auditPath | 审计XML位置，同目录生成result.json、恢复副本和预览 |
| reviewedContinuedTables | 实际拆表后经人工看过重复表头及续表标识的表格序号；未核对时不设置 |

不要把旧文章的story ID、预计页数或图源指纹直接复制给新稿。核对输入须来自相应Word；换原稿时重新生成。当前字体、栏宽、灰框与底线参数对应已验证的本刊模板，其他模板须另做适配和验证。

## 阻断与仍需人工核对的部分

自动检查包含实际字体/字号/行距及复合字体映射、缺字/缺字体、全文段落与表格数据、上下标、图源指纹/尺寸、图题5 pt、灰框、统一底线、末页齐底、图居中、结论中插图、表头、行高和文字/单元格溢出。

整页正文使用共同底部基准。首页收稿/基金栏和图之间的局部文本框不强压到整页底线；末页做双栏平衡。正文在14.8—16 pt内调整；禁止用原生文本框底端对齐、垂直分散、上内边距或首行偏移凑齐底。仍不足时使用已确认的表高、局部字距及小幅图尺寸调整，不突破行距范围。检查的是实际末行，不能仅检查框边。

检测到表格跨框时，完整入口要求核对接续处重复表头与必要的“续表”标识，未核对会阻断。复制模板续表框并自动预留位置尚未实现，不应声称已经验证。复杂公式自动送Illustrator转轮廓尚未实现；这次赵志威使用先前已验证的轮廓PDF，当前程序锁定其文件指纹/尺寸并检查链接，公式语义与形状仍需看源稿及预览。

标题语义、图表与上下文的合理断点和审美取舍仍要逐页看。所有检查通过表示本轮技术门槛通过，不替代用户终审。

## Adobe 外预检、版面计划与单写入队列

批量任务先写任务清单JSON，至少包含`taskId`、`author`、`sourceWord`、`articleJson`、`figureDirectory`和`outputDirectory`；有表格、公式时再提供`tableJson`、`formulaManifest`，可用`expectedPages`记录文件名给出的页数预算。运行：

```powershell
2-导入_InDesign/New-JournalLayoutPlan.ps1 -TaskPath <任务清单.json>
```

命令完全在Adobe外检查输入存在性、图题与图号、原图路径和命名、SHA256、尺寸、PDF可解析性、可见字体描述符的`CapHeight`及异常大白边，同时清点正文块、表格和公式清单。结果为`layout-plan.json`：`needs_input`表示缺图、多候选、命名异常、PDF损坏、字体高度字段缺失、巨大白边或公式清单缺失，禁止进入Adobe；`ready`才可排队。版面计划列出单栏、双栏、并排或三图通栏建议、预计页数和跨栏断点。建议必须结合实际预览复核，程序不会借此自动移动正文或改图。

队列入口为`Invoke-JournalBatch.ps1`。`Register`幂等登记，清单改变时退回`preflight`；`Preflight`生成计划并写入`ready/needs_input`；`Acquire`分别为`InDesign`和`Illustrator`发放单一租约，第二个写任务会被拒绝。Illustrator完成后以相同`leaseId`调用`Complete`登记公式已准备；InDesign完成后进入`rereview`，必须提供实际核查证据才能`Pass`。异常退出使用`Release`和原租约恢复，不删除任务状态。示例：

```powershell
$q = 'C:\QA\journal-queue'
2-导入_InDesign/Invoke-JournalBatch.ps1 Register -QueueDirectory $q -TaskPath <任务清单.json>
2-导入_InDesign/Invoke-JournalBatch.ps1 Preflight -QueueDirectory $q -TaskId <任务ID>
2-导入_InDesign/Invoke-JournalBatch.ps1 Acquire -QueueDirectory $q -Lane InDesign -TaskId <任务ID>
# 保存返回的leaseId；Adobe装配完成后：
2-导入_InDesign/Invoke-JournalBatch.ps1 Complete -QueueDirectory $q -Lane InDesign -LeaseId <leaseId>
2-导入_InDesign/Invoke-JournalBatch.ps1 Pass -QueueDirectory $q -TaskId <任务ID> -EvidencePath <核查报告>
```

队列只调度，不自行调用InDesign或Illustrator；Adobe调用必须由持有租约的单一工作进程执行。`tests/run_batch_preflight_regression.ps1`不启动Adobe，验证缺图、巨大白边、状态恢复和单写入互斥。

每个成功步骤后用`Checkpoint`写入统一恢复点；输入JSON的`schemaVersion`当前为1，必须包含`taskId`、`currentTemplate.version/status`、`currentArticle`、`stage`、`inputs[{name,path,sha256}]`、`outputPath`、`rulesVersion`、`configVersion`、`failure{classification,reason}`、`nextAction`和`forbiddenReuse`。入口会重新计算全部输入SHA256，任一输入缺失或与声明指纹不一致就拒绝保存；成功后原子写入`queue/checkpoints/<taskId>.json`，并把`checkpointPath`和`checkpointSha256`写回任务记录。示例：

```powershell
2-导入_InDesign/Invoke-JournalBatch.ps1 Checkpoint -QueueDirectory $q -TaskId <任务ID> -CheckpointDataPath <检查点输入.json>
2-导入_InDesign/Invoke-JournalBatch.ps1 Resume -QueueDirectory $q -TaskId <任务ID>
```

`Resume`先核对检查点文件自身指纹，再核对全部输入路径和SHA256，只在未变化时返回`verified:true`及`nextAction`。任务清单变化会自动清除旧检查点关联，避免恢复到旧规则、旧模板或失败版；清单未变化的幂等`Register`保留现有检查点。检查器误报或配置修正可以针对同一副本重新检查，只有模板、源数据、整体装配逻辑错误或文档状态不可信时才废弃当前副本。
## 合入真实目标环境

先将正式目标复制为QA并在InDesign打开，源文章也必须为QA。`append_article_to_target.jsx`接受`JournalAppendJob`：`sourceName`、`targetName`、唯一`styleToken`、`resultPath`。脚本追加文章页，临时隔离源正文样式并在finally恢复源名；合入后逐对象恢复源页面相对坐标、逐段恢复keepWithNext并重建故事绑定。它仅保存目标QA，不保存正式输入。

结果JSON含`start/end/bindings/restoredItems`。用它更新文章配置，另设置`articlePageRange:[start,end]`，将figurePanels及widePanelBoundaries页索引加start。然后用Invoke-JournalLayout.ps1的Check及ExportPreview。整期目标模式只允许Check，避免通用Apply改到其他文章。源稿内容/表格/上下标仍照常核对，原生预检检查完整目标，而非仅截取文章。

已实测源文章原位合入`10.indd`的全新副本并全项通过。配置、绑定、模板和文章输出均留本机，不提交实稿。

## 源表字符格式、局部齐底与图上下留白

先以Get-JournalTableFormatting.ps1 -SourceDocx <只读原稿> -OutputPath <本机源表格式.json>提取直接运行格式与纵向合并，将tableTextRuns、mergedEmptyCells加入文章配置。tableTextRuns按源表的行、格、字符偏移记录text/italic/position，应用时先结构合并、再基准9/12、最后恢复字符格式。表格缺少源字符资料将被TABLE_SOURCE_FORMAT_REQUIRED拦住；复杂继承样式需另核源，不得默认正体。

localBottomPairs:[{frames:[左框序号,右框序号]}]核对局部表边与文字可见下缘。balancedFigureGaps:[{number:图号,upperFrames:[...],lowerFrames:[...],tolerance:0.5}]比较并平衡通栏图上下实际留白；Apply在整栏平衡后执行。图数据XML里的通栏判断使用显式括号，避免旧ExtendScript嵌套条件表达式误分类。

新增FUND_JUSTIFICATION、TOKEN_LINE_BREAK、TABLE_SOURCE_FORMAT、LOCAL_BOTTOM、FIGURE_WHITESPACE及FORMULA_ELLIPSIS阻断项。数字与单位的断行比较实际行首索引，不能比较baseline（上下标在同一行也有不同baseline）。上下标映射用显式if返回InDesign枚举，避免嵌套条件表达式把下标写成上标。

tests/run_table_tokens_regression.ps1 -ConfigPath <独立文章配置> -ReportPath <本机报告.txt>用独立QA夹具故意破坏上述规则并要求审计拦住。正式文件不参与故障注入。字体指派若在目标环境解析成Times New Roman (OTF)等旧别名，立即阻断；通过现有IDML字体资源修复器生成新QA，再重开与完整预检，不能仅信app.fonts中的安装状态。
## 原生粘贴公式与核验配置（2026-10-20）

当前用户要求公式直接粘贴为原生轮廓，历史轮廓PDF置入方式停止用于新稿。AI准备结果通过Illustrator复制、InDesign preferPDFWhenPasting=false粘贴；确认原生Group且allGraphics=0，再锚定公式段。恢复邻接正文样式，保留变量斜体及上下标；不要让说明文字继承公式样式或右对齐。

assets中的公式登记 placement=native-vector、AI来源路径及SHA256、实际宽高、basePointSize=10.5；对象标记formula-native-paste=true、formula-base-point-size=10.5。requireNativeFormulaPaste=true阻断链接公式；graphicCount仅计实际链接图形。检查包括原生对象类型、无图形链接、100%缩放、尺寸和字号来源标签，不能以这些标签代替实际轮廓目检。

widePanelFrameBreaks使用正文框索引对（如[[9,10],[13,14]]）检查跨通栏图的段中断排；整期复制后正文框索引保持文章内部顺序。figurePanels的pageIndex须转为整期绝对页面索引。

王莹雪实际交付为262—268页、7页、152段、27个单元格、58个上下标字符；单篇及整期副本均通过Check，整期副本关闭重开后再次通过。六幅位图可等比缩放且不生成作图交接清单。

## 小型QA模板初始化

批量装配前用 `Initialize-JournalQaTemplate.ps1` 从已确认且已注册角色的独立QA稿抽取连续6—8页，生成只含页面结构的QA模板。入口只读源INDD，先用 `saveACopy` 完整继承主页、样式和复合字体，再在副本中裁掉范围外页面、清除稿件图表及文字，保留`front`、`body`、`footer`、`doi`故事框、灰框和分隔线锚点。文章特有的通栏前置框会从空模板移除，后续页恢复为左右两栏标准框；源稿若有未保存修改会中止。输出文件名必须含`QA`、`copy`或`副本`，不得覆盖源稿。

```powershell
.\Initialize-JournalQaTemplate.ps1 -SourcePath "已通过的独立QA.indd" -OutputPath "批量空白-QA.indd" -PageCount 7
.\Initialize-JournalQaTemplate.ps1 -SourcePath "目标环境.indd" -OutputPath "批量空白-QA.indd" -StartPageIndex 249 -PageCount 7
```

`StartPageIndex`从0计数；第二个例子表示抽取InDesign第250页起的7个页面。指定页段必须已有`front`、`body`、`footer`、`doi`角色标签；未注册的正式目标不能靠位置猜测固定锚点。

首次成功后会写出同名`.template.json`，记录源文件与初始化脚本SHA256、页段、输出SHA256和结构数量。完全相同的再次调用直接返回`status: reused`，不会重新取得InDesign文档；参数或产物已变化时拒绝覆盖。`-ValidateOnly`只检查路径、QA边界与计划，不调用Adobe。实际生成后仍须在该模板装入一篇文章，并按完整Check和预览流程确认复合字体、固定锚点及主页显示；结构清单不能代替视觉验收。

初始化器会给原生对象登记六个必需槽位：`front-title`、`front-abstract`、`body-left`、`body-right`、`received-fund`、`doi`。当前刊物题头与摘要位于同一个已通过的原生故事框，因此前两个名称是同一对象的显式别名；它们不代表脚本重新造了两个框。正文左右栏必须属于同一故事，所有槽位必须各解析到唯一对象，否则模板生成失败。

## 槽位装配与原生组件仓库

`journal_slot_template.jsxinc`只解析模板里的槽位并填入内容，不调用`textFrames.add()`重建首页。`Invoke-JournalSlotAssembly.ps1`把整篇槽位数据和组件清单压成一次配置，只执行一次InDesign `DoScript`；调用内暂停实时重绘和后台预检，批量填入后统一重排并保存。目标必须是QA/copy/副本，正式源仍只读。

可复用组件统一带`journal-component-key`、`journal-component-hash`、`journal-component-kind`三项标签。允许种类为公式、DOI、收稿基金、灰框和续表标题。仓库接口支持把已经通过的原生对象导出IDMS、从已打开的“组件仓库.indd”按键与哈希`duplicate()`，或从IDMS置入；置入后必须再次匹配键与哈希。组件清单可给出文件SHA256，入口会在进入Adobe前拒绝已变化的IDMS。公式缓存生成的IDMS可直接走同一置入接口，不再经过Illustrator或剪贴板。

```powershell
.\Invoke-JournalSlotAssembly.ps1 -ConfigPath "本文槽位装配.json" -PlanOnly
.\Invoke-JournalSlotAssembly.ps1 -ConfigPath "本文槽位装配.json"
```

配置至少含`documentPath`，可含`doiText`、`bodyText`、`frontmatter`及`components`。每个组件明确`mode`（`idms`或`library`）、`kind`、`key`、`hash`、`pageIndex`；IDMS组件另给`idmsPath`和文件`sha256`，仓库组件给已打开文档名。`bounds`是显式落位坐标，续表标题仍须由版面计划给出目标页和坐标；该接口不根据粘贴板位置猜测接续栏。运行`tests/run_slot_component_regression.ps1`可在不调用Adobe的情况下验证槽位、组件身份、单次JSX和禁止重建首页框。

## 无弹窗题头与摘要模块

`2-导入_InDesign/journal_frontmatter.jsxinc` 提供 `JournalFrontmatter.apply(document, frames, data, config)`，供持有 InDesign 单写入租约的装配程序调用。模块不读取当前选择、不打开文档、不显示对话框；调用方负责一次打开、保存、导出和关闭，并接收模块返回的 `{ok, log, measurements, plan, warnings}` 结构化结果。错误直接抛给调用方写入队列日志。

`frames` 显式传入 `front`、`footer`、至少两个 `bodyColumns`，以及可选的 `topGray`、`bottomGray`、`separator`；`data.front` 和 `data.footer` 的每段都要带明确 `role`，不得再按文字内容猜题头角色。`config.styleMap` 把角色映射到模板段落样式，`frontAnchor` 固定摘要框上、左和宽度，`footerAnchor` 固定收稿/基金框左、宽和底部。基金内容增加时只向上生长，并强制双齐末行齐左。

双行英文标题由 `enTitleUpperLeadingPt` 单独调上行，末行使用 `enTitleLastLeadingPt`；`enTitleAuthorBaselineGapPt` 保持标题末行到作者的模板间距。摘要框只收底部。正文起点、上下灰框、收稿/基金间隔按实际字形边界计算；正文框保持顶端对齐、上内边距0，不用框内空白凑间距。

纯规划接口 `planEnglishTitle` 与 `planGeometry` 可在 Adobe 外运行。修改模块后先执行：

```powershell
.\tests\run_frontmatter_module_regression.ps1
```

该回归拒绝交互调用，并检查固定上起点、正文按实际字形起排、灰框参数、收稿/基金固定底部与向上增高。它是静态几何回归；首次接入具体模板仍须在专用QA副本中完成完整Check和预览目检。

## 公式内容哈希缓存与IDMS复用

公式缓存键由WMF源文件字节和规范化规则组成。当前规则记录10.5 pt、≤/≥使用SimSun、全部轮廓化以及AI/PDF/PNG审计格式；规则改变时必须提升`RuleVersion`，旧缓存不会误命中。先在Adobe外生成计划，确认缺失和失效项，再串行构建：

```powershell
.\Prepare-JournalFormulaCache.ps1 -InputDirectory "提取公式目录" -CacheRoot "本机公式缓存" -ManifestPath "本文公式缓存清单.json" -Numbers @(1,2,3) -Mode Plan
.\Prepare-JournalFormulaCache.ps1 -InputDirectory "提取公式目录" -CacheRoot "本机公式缓存" -ManifestPath "本文公式缓存清单.json" -Numbers @(1,2,3) -Mode Build
```

缓存项保存`formula.ai`、`formula.pdf`、`formula.png`、字号审计和`asset.json`；命中时逐项复核SHA256。源内容、规则或缓存产物改变会成为miss/invalidated，并写入JSONL事件日志。AI/PDF/PNG仅用于生成和审计，排版文件不链接公式PDF。

装配程序保持目标QA文档已经打开，对每个公式调用`Use-JournalFormulaNativeCache.ps1`。首次使用从缓存AI复制原生轮廓组，锚定后导出同缓存键的`formula.idms`；后续文章直接置入IDMS，不再打开Illustrator。接口只接受唯一的文字标记或已锚定占位对象，要求结果为Group、`allGraphics=0`、100%缩放，并写入缓存键、源哈希、规则版本和10.5 pt来源标签；同时写入通用组件键、源哈希和`formula`种类，使该IDMS可由槽位装配入口批量复用。`-PlanOnly`只报告`paste-and-cache`或`reuse-idms`，不会调用Adobe。

```powershell
.\Use-JournalFormulaNativeCache.ps1 -ManifestPath "本文公式缓存清单.json" -Number 1 -DocumentName "作者_试排_QA.indd" -MarkerText "⟦EQ-001⟧" -PlanOnly
.\Use-JournalFormulaNativeCache.ps1 -ManifestPath "本文公式缓存清单.json" -Number 1 -DocumentName "作者_试排_QA.indd" -MarkerText "⟦EQ-001⟧"
```

该接口拒绝打开InDesign文档，目标文档未打开会报`FORMULA_DOCUMENT_NOT_OPEN`；Illustrator只关闭本次自己打开的公式文档。运行`tests/run_formula_cache_regression.ps1`可在不调用Adobe的条件下验证源+规则键、产物失效、计划清单、IDMS复用计划和单文档所有权约束。首次Adobe集成仍需在专用QA副本中验证IDMS置入返回的对象类型、锚点位置及关闭重开后的原生Group状态。

## 图片缓存、复杂度流水线与可恢复状态

`JournalPreflight.psm1`按图片文件SHA256保存元数据，缓存记录包括尺寸、PDF页框、白边、字体、位图/矢量/混合类型和单栏推荐缩放。任务清单可用`assetCacheDirectory`指定共享缓存目录；未指定时使用输出目录下的`.asset-metadata-cache`。原图内容未变时只计算哈希并读取记录，哈希变化才重新解析和渲染。

版面计划按实际内容选择`fast-graphics`、`standard`或`formula-dense`。图源不唯一、异常白边、PDF不兼容、公式清单异常，以及双栏图表找不到唯一前置引用段时，统一写入`exceptionSummary`并返回`needs_input`，不得进入Adobe。每个双栏图表同时生成`widePanelBoundaries`，以`paragraphText`和`objectNumber`标识完整前置段，并设置`panelBreakAfterParagraph`；面板只能在该段结束后落位。该标记不会强制长段`keepAllLinesTogether`，装配器应根据剩余容量决定让段落正常跨栏或整体后移。

队列额外保存稳定的`workflowStage`和中文`stageLabel`：`extracted`（已提取）→`figures-approved`（图源通过）→`formulas-approved`（公式通过）→`initial-layout-complete`（初排完成）→`key-pages-approved`（关键页通过）→`full-article-approved`（整篇通过）→`merged`（已合入）。旧的`ready/layout/rereview/passed`状态仍保留以兼容现有入口。关键页、整篇和合入使用`Advance`并提供证据文件；`Pass`保留为旧流程的一步式核查入口。

`timings`记录Word提取、预检、公式处理、InDesign装配、关键页预览、整篇导出和合入毫秒数。预检与Adobe单写入租约自动计时；外部提取/导出程序用`RecordTiming -TimingStage ... -ElapsedMs ...`写入真实耗时。运行`tests/run_asset_cache_pipeline_regression.ps1`可在不调用Adobe的条件下验证缓存命中与失效、三流水线、集中异常、跨栏边界、状态恢复和耗时记录。

## 2026-10-21 终检反馈对应的通用修复入口

`Replace-JournalFormulaNative.ps1 -ConfigPath <文章检查配置.json> -Numbers @(1,2,3) -BackupDirectory <本机备份目录>` 用于已有QA稿的公式替换。先保存可恢复副本，再复制AI轮廓并明确激活目标InDesign窗口；粘贴结果要求Group、无链接、100%缩放，保持原锚点和布局占位。配置同步记录AI指纹及实际链接图形计数。`-SourceAi`仅用于单个公式显式指定派生AI。

`Repair-JournalFormulaAssets.ps1` 先对WMF连续文字的当前位置记录生成等价显式坐标副本，再交给Illustrator；不修改源WMF。Python解释器可用`-PythonExe`或`JOURNAL_PYTHON`指定。缓存规则更新为`formula-outline-v2-explicit-wmf-position`，避免复用旧叠字结果；轮廓仍须目视核对。

文章检查配置提供`sourceLogicalArticle`，指向Word提取的logical-article.json；完整检查入口自动载入blocks用于逐字符斜体及上下标检查。`formulaNumbers:[{number:素材序号,displayNumber:null}]`标记原稿不编号的独立公式；装配器也从源公式段读取实际编号，不使用素材序号补号。

`journal_tracking_request.cjs <measurement.json> <bottom-plan.json> <requests.json>` 从阻断栏和末页平衡范围选择有限的正文、参考文献与简介候选，交给`Export-JournalLayoutMeasurement.ps1 -TrackingRequestPath ...`进行真实试排。随后由`journal_reflow_plan.cjs`判断合法字距、内容端点及范围外行流是否保持；不使用估算结果直接宣称通过。每次实际修改后重新测量、生成底齐方案、执行完整Check并查看预览。

本轮新增回归：`tests/run_review_contract_regression.cjs`、`tests/test_wmf_text_positions.py`和`tests/run_review_contract_indesign.ps1`；最后一个在真实InDesign脚本引擎中检查共享函数，不修改文档。

返修已有任务使用`Invoke-JournalBatch.ps1 -Action Rework -QueueDirectory <本机队列> -TaskId <任务ID>`。入口保留旧任务记录副本，清除旧证据/检查点，通过后重新走检查和预览；持有租约的任务禁止返修复位。不得将旧passed/merged状态沿用到新修订。

原生公式保留布局占位时，`formula-layout-padding`必须无填充、无描边。默认对象样式可能向新矩形带入灰线；替换入口清除对象样式后设透明属性，完整检查用`FORMULA_PADDING`阻断可见外框。不能清除真实公式笔画。

续排压缩分别使用正文14.8—16 pt、参考文献和简介12.6—13.4 pt，并验证范围实际所属段落角色。需要多个局部调整时，只允许每一步减小真实容量差距且不破坏已可行栏；中间结果仍为unchecked，最终需重新测量和完整Check。

单行独立公式保留段落基础行距与原生高度所需空间，避免沿用旧PDF配置的大行距；多行公式分别按各行高度处理，不能让短行继承高矩阵的行距。显式执行布局配置回放后再次校正原生公式行距。已有已排QA稿的恢复流程不应无条件重新回放整套布局配置。

当普通满页相邻栏的一侧缺少一行时，规划器可在正文14.8—16 pt范围内微增前一栏的合法行距，让文字自然续入短栏；不改文本、不插空白、不改变公式字号。方案仍需重排、重新测量与完整检查，不把估计当成通过。

## 2026-10-21 合入验收修订

独篇通过不代表整期可用。交付前必须在用户指定整期文件的QA副本中合入，再比较实际字符格式、制表符/制表位、合并关系、公式原生对象和页面坐标，运行文章范围质量门禁。禁止用原始同名样式直接复制页面作为已验收的交付方式：已实测会把10.5pt复合宋体正文替换为目标同名样式的11pt Cambria，并使首页摘要溢出。

`journal_merge_safety.jsxinc`仅用于独立导出QA副本：把段落/对象/表格/单元格样式移入唯一父组，字符样式按定义比较并复用，保留原样式末级名称及数值。生产编辑稿不做此移动。需要续修时使用原编辑稿的最新副本；导出副本有独立的检查点与源路径。普通页复制仍可能因目标页的左右侧和版面调整造成坐标迁移，必须由`append_article_to_target.jsx`恢复对象相对坐标，并按目标左右页边距平移。新增节默认不得保留。任何源稿或目标已有页面的格式变化均阻止交付。

英文作者单位原段落样式为25pt；多行单位只对内部行局部用15pt，末行保留25pt。恢复该定义之后必须重新计算首页内容高度和正文可用空间，不能只改样式后直接宣称通过。
