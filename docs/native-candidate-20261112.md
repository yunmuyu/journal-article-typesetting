# 2026-11-12 原生排版开发候选

本候选沿用现有 InDesign 初排、检查和预览入口。新增库的接入程度如下。规则按 [期刊文章排版执行标准](期刊文章排版执行标准.md) 执行。

## 版面规则

- 正文每栏用独立文本框，按阅读顺序跨栏、跨页串接。通栏图表与正文分框，续表可由自己的独立故事串接承载。多篇顺排进入同一可编辑 INDD，续排后检查前篇是否保持原版。通栏对象上方如果只留一行跨页续文，整行通栏。
- 普通正文栏先检查栏底是否为标题或标题组。标题先保留应跟排的正文，小节标题后同栏有一行即可。两栏各自以统一底线为目标，先在正文允许范围内调行距，再试局部字距，必要时组合两者并复核断点。摘要沿用模板行距，正文填白时保留摘要设置。首页左栏为收稿和基金留位。末页按两栏实际末行基线平衡，差值上限 0.1 mm。
- 公式主字号 10.5 pt，排版过程中保持经核对的对象大小。局部容量不足时调整正文、栏位或断点。续表允许 n＋1，按完整数据行、合并单元格及实测空间选断点，续页重复真实表头和单位说明，并加续表标记。行数比例由实排决定。
- 普通单栏表在总宽范围内分配列宽，检查单元格溢出。双汉字、公式、表头合并及确有对齐差异的数值列按各自约束处理。上下通栏表夹正文使用执行标准中对应的表高与间距调整顺序。

## 回归与验收

在仓库根目录运行 `node tests/run_native_candidate_regressions.cjs`。需要 Node.js 和 PowerShell 7，逐项执行固定清单，任一失败时退出码非零。回归入口使用合成数据，无 Adobe 调用。Windows 字体测量可另运行 `pwsh -NoProfile -File tests/run_offline_candidate_regressions.ps1 -WithWindowsTypography`。

离线断行、占高估算和底线求解用于产生备选。含公式正文的新断点、前后页衔接、复杂续表及全篇渲染需要原生测量、保存重开和检查。初排交接以内容、格式、结构和可编辑性为准，待人工完成的换行、分页、留白和齐底应在交接时标清。

## 本轮实际结果与未通过项

- 候选统一入口 31 项通过；受影响原生模块的 70 个 Node 检查通过。Windows WPF 字形回归通过。队列配套原子写入缺失已修正：修前 8/8 轮复现双写，修后 16/16 轮四路竞争仅一个获租约。
- 本地六页可编辑交付完成，保存重开后正文、表数据一致，103 个公式几何大小不变，前 14 页保留；普通页两栏及表间正文、末页差值均在本次 0.1 mm 内。首栏为收稿区保留专用底线。续表采用实际可行的 7＋1，这不是通用固定断点。
- 上述交付包含人工指定区域的组合调整，不是从 Word 全自动二次实排成功。最后版 `alignFrameBodyLeading` 在真实交付副本上再次扰动并修复：一轮恢复目标底线，正文及栏断点不变、无溢出；关闭测试副本不保存，不覆盖交付文件。
- 本轮全过程约 13 分钟，含准备、失败尝试和逐页预览。首页组合调整约 8.9 秒，只是该局部步骤。旧逐字符方案约 118 秒，已改用旧模块的范围批量修改；不能将局部耗时作为整篇吞吐量。
- **仍未通过**：离线求解器的首页公式回排、第 18 页的独立预测齐底、换栏高度误差校准、第二次整篇自动实排。交付副本相应页面齐底已解决，不等于离线预测链路通过。新增云端补测和重跑保持暂停。

## 保留但未接入默认入口的旧工作

- 同一打开会话内多候选试排的本地计时脚本含个案对象选择，尚未作为通用命令发布；其范围批量修改、断点守护和失败恢复能力在已有 `leadingStep` 及新框级函数复用。不存在“全部已自动调用”的承诺。
- 本地外部表格窗口选择器仍有旧的续页两行约束，尚未移入此候选；不能用它覆盖本候选允许 n＋1 的原生续表检查。云端数值筛选入口保留，但实测行高到块/栏的完整转换仍未完成。
- 队列式总稿续排包装器、通栏补齐原型和个案参数回放未发布为已验证全流程。独立故事范围、前篇保护及装配库已保留，仍需显式调用、保存重开和全文验证。
- 位图与续表分框试排只在独立副本使用，拒绝后必须丢弃副本。位图已加正文故事及锚点段落归属保护；其尺寸启发式和实际应用不属于全篇自动验收证据。

真实 Word、图源、字体、首次测量及原生验证记录仅保存在本机和既有私有交接目录；仓库只含程序、合成回归及本验证摘要。
